# dots 简体中文桌面客户端

实验性源代码版本，复用 BB 的界面与控件，由 Lorca 负责身份、加密、同步、模型、权限和运行端。当前界面默认使用简体中文；对话内容、工具输出、机器人/供应商名称、协议字段和命令保持原文。

## 启动

需要 Node 22.19 或更新版本。请使用独立的新目录：

```sh
git clone --branch feat/lorca-desktop https://github.com/charlzyx/bb.git
cd bb
node apps/lorca/scripts/focused.mjs install
node apps/lorca/scripts/focused.mjs check
node apps/lorca/scripts/focused.mjs desktop
```

首次启动桌面应用时，脚本可能下载官方 Electron 运行时。请另行启动你要连接的 Lorca CLI。

默认连接 `ws://127.0.0.1:4862/ws`。支持本地令牌认证的服务所使用的现有 `serve-token` 只在主进程读取，不进入界面。应用不会创建、恢复或复制身份，不会自动更改中继配置或启动运行端。

如已有隔离的开发服务，请使用与该服务对应的数据目录和端口：

```sh
LORCA_HOME="$HOME/.lorca-dev" LORCA_PORT=4863 node apps/lorca/scripts/focused.mjs desktop
```

仅在已确认本机服务不校验令牌时，手动选择本地兼容连接（不校验令牌）：

```sh
LORCA_ALLOW_LEGACY=1 node apps/lorca/scripts/focused.mjs desktop
```

兼容模式只允许回环地址，并明确显示警告。认证失败时不会自动降级。

## 三类连接各自使用原来的认证方式

- dots → 本机 Lorca 服务：本地令牌认证使用现有 `serve-token`；本地兼容连接（不校验令牌）必须显式选择。这里不使用 OAuth。
- Lorca → 中继 / 已配对设备：仍由 Lorca 原有身份、加密和同步协议管理；dots 不更换这套机制，也不创建身份。
- Lorca → 模型供应商 / MCP 服务：由具体服务决定是否使用 API key、OAuth 或其他认证。文档中“未支持 OAuth”仅指这些可选服务的网页登录入口，没有说 Lorca 本地连接需要 OAuth。

## 目前可用

- 聊天、附件选择、发送/停止、排队消息、审批、历史分页和重连保护
- 桌面设置页：连接、偏好设置、模型与机器人、执行器、MCP、自动审批
- 当前应用会话内更改连接地址和明暗外观
- 查看脱敏运行状态，编辑现有机器人的供应商、模型、推理级别及执行器
- 在隔离安全窗口配置 API-key / 自定义供应商和 MCP；主聊天界面不接收密钥或原始配置
- 明确确认后启停、重连、重新加载或删除 MCP，编辑账号级自动审批开关与规则
- 中文按钮、菜单、说明、错误、日期与无障碍标签

运行端和供应商状态是 Lorca 上报的信息，不代表客户端进行了实时连通性或凭据测试。未上报的工具数量显示为未知。

每个机器人只有一条私聊。“开始聊天”会打开或创建该机器人的私聊；已有历史会保留，不会建立独立的新会话。群聊是不同的上游功能，目前没有用它来模拟多条私聊。

## 头像与应用图标

机器人头像来自当前 Lorca 数据目录已有的文件缓存。会话列表、会话标题与机器人消息按真实机器人关联显示；群聊组合显示机器人头像。当前协议没有独立用户头像字段，用户使用人物图标。没有缓存、格式不支持或读取失败时回退到机器人的符号和颜色，不影响聊天。

主进程只读取当前已知机器人的缓存文件，校验路径、类型、大小和像素尺寸后重新编码；界面不接收原始路径或附件元数据，也不会为头像自动注册设备或下载资源。自定义服务目录请通过启动时的 `LORCA_HOME` 指定。

原生应用、About 与 Dock 使用已选定的陶瓷幽灵素材，保持原图构图和配色，采用预览中相同的 macOS 风格连续圆角及约 80.5% 主体比例。它不是 Apple 官方模板。开发包包含 16 至 1024 像素的七级图标；应用内侧栏、空态、favicon 与安全设置窗口使用同一幽灵图形，保留 dots 文字；真实机器人/用户头像及其回退图标不受影响。素材来源、商用许可说明与可复现脚本见[图标归属](artwork/NOTICE.md)。原生效果需要重新打包验收，旧包不会自动更新。

## 边界

机器人模型与执行器是机器人级设置，会影响使用它的所有私聊、群聊及后续任务；不存在只改当前会话的协议接口，也不会迁移已运行任务、记忆或 MCP。所有持久变更都有原生确认，版本过期或账号/连接变化会拒绝提交。

自动审批关闭时更严格：Shell 和有副作用的插件操作逐次询问。开启后才使用模型审核和允许规则；没有默认全部允许。规则是整表替换，保存前会核对完整规则和当前版本。协议没有原子条件写入，因此最后一次读取与写入之间仍可能发生其他客户端修改。

供应商配置由服务端保存并同步到当前账号；现有密钥不回显。未知有效连接地址时需明确填写 URL，避免向无法确认的默认目标发送凭据。MCP 保存、启用、重连或重新加载可能运行程序；删除还会移除该服务凭据、插件目录及关联审批规则。保存、删除、启停和重新加载还可能一起应用整个 MCP 文件中其他尚未加载的磁盘变更，甚至启动当前列表中没有的程序。列表只能展示已加载信息，原生确认会明确这一完整文件作用范围；上游没有预览/条件写入接口。

OAuth 网页登录、机器人访问授权、隐藏单个 MCP 工具、服务启停和中继编辑仍需在 Lorca 完成。固定上游协议支持自动审批供应商与模型字段，但客户端目前尚未提供相应编辑控件，也不会发送这些字段。外观和连接地址目前不承诺跨应用重启持久保存。详见[可编辑设置协议](../../docs/lorca-editable-settings.md)。

云端验证使用确定性数据和本机模拟服务，不访问真实账号、中继或模型。macOS 源码运行实测另行进行；尚未提供签名、安装包或正式发布版本。详见[验证记录](../../docs/lorca-verification.md)与[设置能力对照](../../docs/lorca-settings.md)。

## 设置命令行与开发接口

非敏感设置可通过同一套原生事务执行，例如：

```sh
node apps/lorca/scripts/focused.mjs cli settings-action '{"kind":"bot.update","botId":"机器人ID","model":"模型ID"}'
```

必须在交互式终端核对实际变更并输入“确认”；不支持重定向、`--yes` 或传入版本票据。密钥和 MCP 原始配置不能放在命令行参数里，这两项请打开 dots 桌面设置中的安全窗口。程序接口复用 `SettingsEditor` 的校验、确认和连接保护，没有确认回调就不能写。取消不算保存成功；结果未知时不会自动重发。

## macOS 独立本地开发包

源码启动仍使用依赖里的 `Electron.app`。`app.setName` 不能改变该宿主的系统菜单名称；macOS About 图标也来自 bundle，而不是仅支持 Linux/Windows 的 `iconPath`。源码模式已显式显示 dots 产品版本 `0.1.0`，但不能据此宣称系统原生品牌全部替换。

已安装依赖和 Electron 的 Mac，可在仓库根目录执行：

```sh
node apps/lorca/scripts/focused.mjs check
node apps/lorca/scripts/package-macos.cjs
```

脚本输出一个全新的 `apps/lorca/dots-macos-dev-随机字符/dots.app` 路径，拒绝覆盖已有目标。它只复制本项目依赖中的 Electron.app，加入构建页面、原生桥、图标、MIT 许可和 ws 运行依赖；不会复制 `.env`、身份、令牌或开发工作区。新副本有独立 bundle 标识、dots 系统名称、四点 ICNS 和 `0.1.0` 产品版本。辅助进程暂保留 Electron Helper 名称。

脚本仅对新副本运行系统 `plutil` 和 `codesign --sign -`，这是无需证书的本地 ad-hoc 校验签名，不是 Developer ID 签名或 Apple 公证，不能当作正式安装包分发。不修改全局 Electron、Lorca.app、Gatekeeper、钥匙串或权限；失败会保留生成目录供检查，不尝试关闭安全限制。

完全退出先前的源码 dots 窗口，再使用脚本打印的实际路径启动；已确认服务不校验令牌时的显式兼容连接示例：

```sh
LORCA_ALLOW_LEGACY=1 "实际输出路径/dots.app/Contents/MacOS/dots"
```

本地令牌认证不要设置 legacy 开关。认证仍由原生桥从原先的 Lorca 数据目录读取，打包不会迁移或修改该目录。新 bundle 的客户端偏好目录可能与源码宿主不同，主题等当前会话设置需要重新选择。

云端验证副本组装、图标格式、隔离输入与命令边界。此前开发包已在 Mac 生成并通过 ad-hoc 校验；本轮安全区和多分辨率图标需要重新生成包后检查 Dock、顶部菜单和 About 实际外观，不能用旧包结果代替。不要在遇到系统安全警告时绕过。

参考：[Electron About 选项](https://www.electronjs.org/docs/latest/api/app#appsetaboutpaneloptionsoptions)、[手动打包](https://www.electronjs.org/docs/latest/tutorial/application-distribution#manual-packaging)。

连接选项描述认证行为，不代表官方存在两代协议。固定参考源码与安装包的行为可能不同，不能只凭版本号判断；详见协议文档中的提交与源码引用。
